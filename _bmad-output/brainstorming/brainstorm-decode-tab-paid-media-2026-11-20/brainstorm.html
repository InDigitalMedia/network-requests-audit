Insight

Paid media’s real questions are platform-and-outcome shaped (‘is Meta getting purchases with value?’), but Decode is organised request-by-request — the mismatch is the core usability gap.

  1. #001

    Question-first entry: chips like ‘Is my purchase tracking?’, ‘Is consent working?’, ‘Will Meta + CAPI double count?’ that filter and highlight only the relevant rows and answer yes/no

  2. #002

    Per-platform scorecard above the rows: Meta – purchase seen, value present, currency present, dedup key present, consent respected – one line per platform

  3. #003

    Funnel coverage grid: standard stages (page view > view item > add to cart > checkout > purchase/lead) x platforms, ticks where an event was seen, blanks are gaps

  4. #004

    ‘What is missing’ findings: expected events not seen, e.g. a thank-you page URL in the paste but no purchase event to Meta/Google Ads

  5. #005

    Value + currency chip on the collapsed row (e.g. ‘£249.99 GBP’) so conversion hits are checkable at a glance

  6. #006

    Order/transaction ID chip on the row so it can be matched against Shopify/CRM without opening the request

  7. #007

    Pixel/account ID on the row, with friendly names mapped in Your setup (‘9988… = Client X main pixel’)

  8. #008

    Consent icons on every row: Ads granted/denied, Analytics granted/denied, decoded from gcs/gcd/asc

  9. #009

    Page chip on the row: which page fired it (dl path, e.g. /checkout/thanks)

  10. #010

    ‘Send to developer’ button per finding producing a ticket-ready blurb: what, where, why it matters, how to fix, who owns it

  11. #011

    Glossary hover tooltips on jargon terms (deduplication, CAPI, consent mode, sGTM, enhanced conversions)

  12. #012

    One-paragraph plain-English headline at the top: ‘Meta and GA4 are tracking purchases correctly; TikTok is missing a dedup key’

  13. #013

    Relabel severities as business impact: ‘Costs you money’, ‘Compliance risk’, ‘Reporting noise’ instead of fail/warn

  14. #014

    Impact phrasing on findings: ‘Purchases may be counted up to 2x in Meta’ rather than technical cause

  15. #015

    Group-by-event view (alternative to group-by-platform): ‘purchase’ group shows GA4, Meta, TikTok side by side

  16. #016

    Cross-platform value mismatch finding: GA4 says 249.99, Meta says 24999 for the same purchase

  17. #017

    Cross-platform currency mismatch finding (GBP on GA4, USD on TikTok)

  18. #018

    Duplicate-fire detection: same event fired twice to the same platform/pixel within one paste

  19. #019

    ‘Explain like I’m the client’ toggle that rewrites findings into client-safe tone

  20. #020

    Confidence label per finding: ‘We are sure’ / ‘Probably’ / ‘Cannot tell from this paste’

Verdict · 109 ideas → 5 insights → 1 route

What the signal actually says

01

One idea in three hats: an ‘Answers’ layer

Question chips + funnel coverage grid + per-platform scorecard are the same thing, an ‘Answers’ layer (platform x outcome) sitting above the request list. This is the headline direction: paid media think in platforms and outcomes, not requests.

Hat 1 · Question chipsHat 2 · Funnel coverage gridHat 3 · Per-platform scorecard
● Headline direction
02

The keystone: a normalised field layer

A normalised field layer in tag-detector.js (Event, Value, Currency, Order ID, Dedup ID, Consent, Page, Pixel ID) mapped from each platform’s param names, like describeEvent(). Build once and it powers row chips, checklist strip, compact table, receipt cards, cross-platform mismatch checks, CSV and Slack export.

◆ Keystone
03

The biggest silent risk is absence of evidence

A green verdict when the purchase never fired. Expected-events (vertical templates, tracking plan import, Your setup client profile) is one mechanism that unlocks ‘what is missing’, unexpected-pixel, and event-name typo checks together.

▲ Silent risk
04

Friction is at the input, not the output

HAR import and a bookmarklet ‘Open in decoder’ via URL fragment remove DevTools and copy-paste entirely – likely the single biggest win for non-specialists, and both keep the zero-network guarantee (fragment never sent; flag the browser-history exposure).

■ Biggest win
05

Findings become forwardable actions

When phrased as business impact + owner + effort (relabel severities, fix-owner chip, spend-at-risk, Send to developer). Per-client memory in localStorage (baseline diff, ignore rules, pixel names, history) turns a one-off decoder into a recurring check.

● One-off → recurring
Constraint held throughout

Zero network requests · single static file + tag-detector.js · no backend.
